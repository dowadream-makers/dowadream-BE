# API 공통 규약

도와드림의 모든 HTTP API가 따르는 약속입니다. 새 API를 만들 때 이 문서와 다르게 해야 하면, 먼저 팀에 말하고 이 문서를 고친 뒤 만듭니다.

## 1. 주소

| 항목 | 규칙 | 예 |
|---|---|---|
| 접두어 | 모든 API는 `/api`로 시작 | `/api/hospitals` |
| 자원 이름 | 영어 **복수형 명사**, 소문자, 단어 구분은 `-` | `/api/symptoms`, `/api/help-requests` |
| 하나 고르기 | 경로에 id | `/api/hospitals/4` |
| 거르기·정렬 | 쿼리 파라미터 | `/api/hospitals?dept=05&lat=..&lng=..` |
| 여러 값 | 쉼표로 이어 붙임 | `?ids=1,4,7` |
| 하위 자원 | 경로를 이어 씀 | `/api/devices/door-01/reports` |
| 관리자 전용 | `/api/admin/**` | `/api/admin/hospitals/4/waiting` |
| 장치 전용 | `/api/devices/**` | |
| 상태 확인 | `/actuator/health` (API 아님) | |

- 버전 번호(`/v1`)는 붙이지 않습니다. 화면과 서버를 같은 팀이 함께 배포하므로, 바꿀 땐 둘을 같이 고칩니다.
- 동사(`/getHospital`, `/createReport`)는 주소에 쓰지 않고 HTTP 메서드로 나타냅니다.

## 2. HTTP 메서드

| 메서드 | 뜻 | 성공 응답 |
|---|---|---|
| `GET` | 읽기. 서버 데이터를 바꾸지 않음 | `200` + 본문 |
| `POST` | 새로 만들기, 보고 받기 | `201` + 만든 것 (보고 수신처럼 만든 게 없으면 `200`) |
| `PUT` | 통째로 바꾸기 (관리자 대기 인원 입력 등) | `200` + 바뀐 것 |
| `DELETE` | 지우기 | `204` (본문 없음) |

## 3. JSON 모양

- 요청·응답 본문은 모두 `application/json; charset=UTF-8`.
- **필드 이름은 camelCase** (`specialistTotal`, `distanceM`).
  - **예외: 장치(ESP32)가 보내고 받는 JSON만 snake_case** (`measured_at`, `people_avg`, `demo_mode`). 펌웨어와 하드웨어 계획서에 이미 정해 둔 모양이라 바꾸지 않습니다.
- **성공 응답은 감싸지 않습니다.** 목록이면 배열 그대로, 하나면 객체 그대로 보냅니다.
  ```json
  [ { "id": 4, "name": "가상 바른정형외과의원", ... } ]
  ```
  (`{ "data": ..., "success": true }` 같은 껍데기를 쓰지 않습니다. 성공/실패는 HTTP 상태 코드로 구분합니다.)
- **값이 없으면 `null`**로 보냅니다. 필드를 빼지 않습니다. 화면은 `null`을 "정보 없음"으로 처리합니다.
- 목록이 비면 `[]` (404 아님).
- 정해진 값 중 하나인 필드(enum)는 **영어 대문자 + `_`** (`RELAXED`, `NORMAL`, `BUSY`, `FULL`). 화면에 보일 한국어 이름은 프론트가 정합니다.
- 단위는 필드 이름 끝에 붙입니다: 미터 `distanceM`, 분 `minutes`, 초 `...Sec`.
- 좌표는 `lat`, `lng` (WGS84, 소수 도).
- id는 숫자(`Long`). 장치 id만 사람이 읽는 문자열(`door-01`).

## 4. 날짜와 시간

- **ISO-8601 문자열**만 씁니다. 숫자 타임스탬프는 쓰지 않습니다.
- 서버가 보내는 시각은 **UTC (`Z`로 끝남)**: `"2026-12-07T01:31:00Z"`. 화면에서 한국 시간으로 바꿔 보여 줍니다.
- 서버가 받는 시각은 **시간대를 꼭 붙여서**: `"2026-12-07T10:31:00+09:00"` 또는 `...Z`. 시간대 없는 값은 400입니다.
- 진료시간처럼 날짜 없는 "몇 시"는 `"09:00"` (한국 시간 기준, 예정).

## 5. 오류 응답

오류는 모두 아래 한 가지 모양입니다 (`common/ErrorResponse.kt`, `GlobalExceptionHandler.kt`).

```json
{
  "status": 404,
  "code": "NOT_FOUND",
  "message": "찾는 정보가 없어요.",
  "path": "/api/hospitals/999",
  "timestamp": "2026-11-23T11:42:25.275Z"
}
```

| status | code | 언제 | 화면에서 |
|---|---|---|---|
| 400 | `INVALID_REQUEST` | 값 형식이 틀림, 필수 값 없음, 검증 실패 | 개발 중 실수. 사용자에겐 "다시 시도해 주세요" |
| 401 | `UNAUTHORIZED` | 장치 키·관리자 토큰이 없거나 틀림 | 관리자 화면이면 로그인 화면으로 |
| 403 | `FORBIDDEN` | 로그인은 했지만 다른 병원 데이터 수정 (예정) | "권한이 없어요" |
| 404 | `NOT_FOUND` | id에 해당하는 데이터 없음, 없는 주소 | "찾는 정보가 없어요" |
| 500 | `INTERNAL_ERROR` | 서버 버그, DB 오류 | "잠시 뒤 다시 시도해 주세요" |

- `message`는 어르신이 봐도 되는 **쉬운 한국어 존댓말**로 씁니다. 화면은 그대로 보여 줘도 됩니다.
- `code`는 화면에서 분기할 때 씁니다. 새 code가 필요하면 이 표에 먼저 추가합니다.
- 서버 내부 정보(스택트레이스, SQL)는 응답에 넣지 않고 서버 로그에만 남깁니다.
- 컨트롤러·서비스에서 오류를 낼 땐 `throw ResponseStatusException(HttpStatus.NOT_FOUND)`처럼 상태만 던지면 위 모양으로 바뀝니다. 메시지를 바꾸고 싶으면 두 번째 인자에 한국어 문장을 넣습니다.

## 6. 인증

| 누가 | 방법 | 대상 주소 |
|---|---|---|
| 어르신(일반 사용자) | **없음.** 로그인 없이 모든 조회 가능 | `/api/hospitals`, `/api/symptoms` 등 |
| 회원(소셜 로그인 후) | 구글·카카오·네이버 로그인 → 회원 토큰(30일) → 헤더 `Authorization: Bearer <토큰>` ([social-login.md](social-login.md)) | `/api/me` |
| 장치(ESP32) | 헤더 `X-Device-Key: <장치별 긴 랜덤 키>`. 서버는 SHA-256 해시만 저장 | `/api/devices/**` |
| 병원 관리자 | `POST /api/admin/login` → 토큰 → 헤더 `Authorization: Bearer <토큰>` **(예정)** | `/api/admin/**` |

- 회원가입은 소셜 로그인만 씁니다(2026-11-25 결정). 로그인은 관심 병원 저장 때만 필요하고, 조회는 계속 로그인 없이 됩니다. 관심 병원은 아직 브라우저에만 저장합니다 ([fe-integration.md](fe-integration.md) 4장).
- 키, 비밀번호, 토큰은 URL 쿼리에 넣지 않습니다(로그에 남음).

## 7. 개인정보

- 증상과 위치는 서버에 **저장하지 않습니다.** 위치(`lat`, `lng`)는 거리 계산에만 쓰고 버립니다.
- 사용자를 식별하는 값(이름, 전화번호, 기기 id)을 받는 API는 만들지 않습니다. 필요해지면 팀과 먼저 상의합니다. 소셜 로그인도 각 회사의 회원 번호와 별명만 받습니다.
- 공공데이터를 보여 주는 화면에는 "자료: 건강보험심사평가원, 국립중앙의료원"을 표시합니다(공공누리 제1유형).

## 8. 목록 크기

- 노원구 병·의원은 수백 곳 수준이라 **페이지 나누기를 하지 않습니다.** 목록 API는 조건에 맞는 전체를 돌려줍니다.
- 수천 건이 넘는 목록이 생기면 `?page=0&size=20`(0부터 시작)을 쓰고 응답은 `{ "items": [...], "page": 0, "size": 20, "total": 153 }`으로 합니다.

## 9. CORS와 주소

- 허용 출처는 환경변수 `CORS_ALLOWED_ORIGINS` (쉼표로 여러 개). 로컬 `http://localhost:5173`, 배포 후 Vercel 주소를 추가합니다.
- 프론트는 서버 주소를 `VITE_API_BASE_URL`로만 알고, 코드에 주소를 직접 쓰지 않습니다.

## 10. 새 API 만들 때 확인 목록

- [ ] 주소·메서드가 1~2장 규칙에 맞나
- [ ] 응답이 camelCase이고 껍데기 없이 그대로인가, 없는 값은 `null`인가
- [ ] 시각은 ISO-8601, 서버 응답은 UTC인가
- [ ] 오류는 `ResponseStatusException`으로 던져 공통 모양으로 나가나
- [ ] 개인정보를 저장하지 않나
- [ ] `api-spec.md`에 추가하고, 화면이 쓰면 `fe-integration.md`에도 추가했나
